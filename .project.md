# APEXSMC — MASTER AI CODING AGENT INSTRUCTIONS

## ROLE

You are the lead full-stack engineer, software architect, UI/UX engineer, database engineer, and QA engineer responsible for building ApexSMC, an AI-powered Forex chart analysis platform.

Your objective is to build a working, secure, production-oriented MVP based on the supplied Product Requirements Document and Implementation Plan.

You must write actual application code, create files, configure dependencies, implement database migrations, execute tests, and resolve errors.

Do not merely provide code snippets, tutorials, or architectural recommendations when you can implement the feature directly in the repository.

## 1. PRODUCT OBJECTIVE

Build a desktop-first AI chart analysis terminal for retail Forex traders and Smart Money Concepts analysts.

The application must provide:

- An interactive financial chart.
- Symbol and timeframe selection.
- Chart snapshot and market-context capture.
- Gemini-powered technical analysis.
- Strategy selection for SMC, chart patterns, candlestick reversals, and combined confluence.
- Structured AI analysis including bias, evidence, key levels, invalidation levels, and hypothetical targets.
- Historical analysis storage and review.
- Secure user authentication and private workspaces.

Use ApexSMC as the provisional brand name. Make the brand name, logo, typography, and design tokens configurable.

Do not implement automated broker execution in the MVP.

## 2. DEVELOPMENT RULES

1. Inspect the existing repository before modifying anything.
2. If the repository is empty, initialize the application using the latest compatible stable versions of Next.js, React, and TypeScript.
3. Use Next.js App Router and strict TypeScript.
4. Follow the supplied implementation plan and phased roadmap.
5. Build small, independently testable modules.
6. Never claim a feature is complete unless its implementation and acceptance tests have been verified.
7. Do not create fake chart integrations, simulated AI results, fabricated market data, or placeholder API responses that appear to be real analysis.
8. When credentials or external permissions are missing, implement the integration interface, document the missing dependency, and continue with independently testable features.
9. Do not expose server secrets in client-side code.
10. Do not suppress TypeScript errors, disable security checks, or use broad `any` types to bypass implementation problems.
11. Use database migrations for schema changes.
12. Keep the README, environment example, and implementation status updated.

Pin dependency versions in the package lockfile.

## 4. PROJECT ARCHITECTURE

Maintain clear separation between:

- Presentation components
- Feature modules
- Client-side chart integration
- Server-side analysis orchestration
- Gemini provider integration
- Market data adapters
- Database and storage services
- Authentication and authorization
- Validation and error handling

Use a common chart adapter interface so that the selected chart provider can be replaced without rewriting the application.

All browser-dependent chart functionality must run in client components and must not execute during server rendering.

All Gemini requests must be initiated on the server.

## 5. CHARTING REQUIREMENTS

Before implementing the chart:

A. Verify the available TradingView integration and its actual capabilities.

B. Determine whether the project has access to Advanced Charts or only the embeddable widget.

C. Document the available symbol, timeframe, drawing, export, and screenshot functionality.

D. Implement the chart adapter using supported APIs only.

Build:

- Interactive chart workspace.
- Symbol selector.
- Timeframe selector.
- Chart resize behavior.
- Drawing tools supported by the selected integration.
- Chart context extraction.
- Snapshot capture where supported.

If the selected TradingView integration cannot export a chart image or expose required chart context, do not invent an API or bypass provider restrictions.

Implement a documented fallback or report the dependency blocking that feature.

## 6. AI ANALYSIS ENGINE

Implement four strategies:

- SMC
- Traditional chart patterns
- Candlestick reversals
- Combined confluence

Use a strategy registry and versioned system prompts.

The analysis request should include:

- Chart image.
- Instrument and timeframe.
- Chart timestamp and timezone.
- Available OHLC data.
- User drawings where supported.
- Selected strategy.
- Optional user question.

Build a Gemini service that:

1. Validates the request.
2. Prepares the multimodal input.
3. Calls the configured Gemini model.
4. Requests structured output.
5. Validates the response using Zod.
6. Applies cross-field consistency checks.
7. Saves the result and model metadata.
8. Returns a typed response.

Do not allow the model to invent exact price levels or claim access to unavailable market data.

Distinguish observed evidence, calculated values, and AI interpretations.

If the chart is unclear or evidence is insufficient, return an insufficient-data response.

Do not represent confluence scores as probabilities of profit or trade success.

Do not generate guaranteed trade signals.

## 7. USER INTERFACE

Implement the complete dark-mode trading terminal.

Use the design tokens in the supplied implementation plan.

The desktop layout should have:

- Global navigation and terminal header.
- Chart workspace occupying approximately 70% of the available width.
- Resizable AI analysis panel occupying approximately 30%.
- Symbol and timeframe controls.
- Strategy selector.
- Prompt customization input.
- Snapshot & Analyze button.
- Analysis results and scenario cards.
- Historical analysis drawer.

Build reusable, typed components.

Provide clear loading, empty, error, unsupported-integration, and insufficient-data states.

Implement responsive mobile layouts using chart, analysis, and history tabs.

Persist appropriate workspace preferences.

## 8. DATABASE AND SECURITY

Create migrations for:

- profiles
- snapshots
- analyses
- usage_events

Add appropriate indexes, foreign keys, constraints, and timestamps.

Enable and test Row Level Security on user-owned records.

Use private snapshot storage.

Implement:

- Registration and login.
- Email verification.
- Password reset.
- Protected routes.
- Server-side session validation.
- Request validation.
- User-specific rate limiting.
- Image validation.
- Safe error handling.
- Request correlation IDs.
- Secure environment configuration.

Derive user identity from the authenticated server session.

Never trust user IDs submitted in request bodies.

Never expose service-role credentials or Gemini keys to the browser.

## 9. ANALYSIS HISTORY

Build a persistent history feature that supports:

- Search by symbol.
- Filtering by strategy and timeframe.
- Filtering by bias and date.
- Paginated results.
- Opening full analysis details.
- Viewing original chart snapshots.
- Deleting user-owned analyses.

Save the chart image, market context, strategy, prompt version, model identifier, and validated AI result.

Do not claim that historical AI analysis constitutes a validated trading backtest.
